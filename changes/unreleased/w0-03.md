### Changed

- Upgrades are safer: before the database schema or the SlotServe version changes, the server saves a snapshot (`data/backups/slotserve-v<old>-to-v<new>-<time>/` with the database, `secret_key` and the dev environment host keys), applies numbered migrations all-or-nothing, and writes `data/migration_report.json`. It refuses to start on a database from a newer SlotServe, and `reset-password`/`set-admin` ask you to start the server once first when the database still needs upgrading.
