### Breaking changes

- Dev environment containers are hardened: no new privileges (setuid programs such as `sudo` stop working; templates that need them, like the built-in desktop, run in a per-template **compatibility mode**), a few capabilities dropped (`ping` no longer works), at most 4096 processes (`SLOTSERVE_DEVENV_PIDS_LIMIT`) and bounded logs.
- A memory limit of 0 (`devenv_memory_gb`, `devenv_cpu_memory_gb`) no longer means "no limit" but the host's memory less max(4 GB, 10 %), so an out-of-memory job is killed inside its container instead of taking the server down. Admins see the value in `/api/devenv` (`hardening`).
- A lane that names no GPUs can no longer start a GPU dev environment (it used to get every GPU of the machine); give the lane its GPUs.
- Every dev environment has its own SSH host key. Existing environments get one on their next start, so `ssh` warns about a changed host key once (remove the old `known_hosts` line and check the fingerprint shown with the environment). Kept environments created by an older version are snapshotted and recreated once on their next start.
- Shared idle environments accept SSH keys only and give accounts only to people who joined them (`POST /api/devenv/shared/<lane>/join`); everyone who had an SSH key is joined to every lane by the upgrade.
- Opening VS Code, a desktop or JupyterLab as a direct port must be confirmed (`confirm_unauthenticated`), since a direct port bypasses the SlotServe login.

### Security

- Storage helper containers always use SlotServe's helper image (`SLOTSERVE_STORAGE_HELPER_IMAGE`) and mount only the folders they work in; new folders are seeded from the environment's image without running it. Before, a custom image could reach everyone's folders.
- The SSH host key is no longer shared by all environments (anyone could read it inside their own container); shared idle environments no longer contain anyone's password hash.
- The built-in VS Code template runs code-server with a password that only SlotServe's proxy uses, so nobody reaches it without signing in to SlotServe.

### Added

- Web UI templates (JupyterLab, desktop, VS Code) start without an SSH key or environment password.
- `POST /api/devenv/preview` shows what an environment would get (GPUs, CPU, memory, mounts, web interfaces, SSH, security settings) without secrets and without starting anything.
