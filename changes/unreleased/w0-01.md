### Breaking changes

- The first admin account now needs a one-time setup code (printed in the log while no admin exists; `slotserve setup-code`). While `SLOTSERVE_INVITE_CODE` is still `change-me`, nobody else can sign up. Installations that already have an admin are not affected.
- Changing API requests from other pages are refused: SlotServe's own origin (`Host` / `X-Forwarded-Host` or `SLOTSERVE_PUBLIC_URL`) or the `X-SlotServe` header is required for requests with the session cookie. Behind a reverse proxy that rewrites `Host`, set `SLOTSERVE_PUBLIC_URL`.

### Security

- An unset or default `SLOTSERVE_SECRET_KEY` is replaced by a random key kept in `DATA_DIR/secret_key`; an explicitly set key is used as before. Copies encrypted with the old default key stay readable.
- `Origin: null`, pages on other ports of the host (direct ports, the web port) and cross-site requests can no longer change anything in SlotServe through a signed-in browser.
