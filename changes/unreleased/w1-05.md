### Breaking changes

- Browser sign-ins are now stored on the server, so everyone signs in once more after the upgrade. API keys keep working unchanged.
- Requests to `/api/` that carry both the session cookie and `Authorization: Bearer` are refused (400 `mixed_credentials`).

### Security

- Changing your password signs out your other browsers; an admin's password reset or disabling an account signs that person out everywhere (also `slotserve reset-password`). Signing in always starts a new session.
- Sign-in throttling locks an account per address (account + IP), so failures from elsewhere cannot lock its owner out. Behind a reverse proxy set `SLOTSERVE_FORWARDED_ALLOW_IPS` so SlotServe sees real client addresses.

### Added

- **Invite links**: admins create `ssi-` links that expire (7 days by default), allow a number of sign-ups (50 by default), can be revoked and can ask for an admin's approval of new accounts. Links never contain the global invite code, which keeps working.
- **Playground API**: `POST /api/playground/chat` lets signed-in people chat with a model that is already serving, without an API key. It is metered as them (`source=playground` in the request log), limited to 20 requests per person and minute by default, never loads or switches a model, and admins can switch it off or restrict it to the default model.
- API keys can expire, show their scope (`llm`) and the address they were last used from; the request log can be filtered by source (API key, environment key, Playground).
- People can list their signed-in browsers and sign them out (`/api/auth/sessions`).
